# Firmware test results

Generated by `make -C firmware test`. The firmware in `src/` runs on the PC against simulated
ADS131M08, microSD and ICM-42688 chips. The input is a 10 s rear-corner drive built from the Adams
mini baja model (`test/make_adams_scenario.py`: spring, damper, bump stop, tire, hardpoints,
masses, 15 mph event speed). The card image is read back with separate FAT and log decoders and
every sample is compared with that input.

## Normal run in numbers

- 30616 samples over 15.67 s, zero dropped, every frame read before the next sample arrived (0 needed to wait for an SD step); RAM ring peaked at 29/256 blocks through 2 simulated 120 ms card stalls; slowest SD block step 173 us.
- Shunt cal reads excitation as 2.4870 V (simulated board: 2.487 V), so the calibration step finds the real rail without a trim pot.
- Peak landing shock force logged 4930 N vs 4929 N in the Adams-based input.
- At 3906.25 sps (256 us between samples) the same code logs 61231 samples with zero drops; ring peaked at 59/256.
- With a 1.5 s card stall (longer than the ~1 s RAM buffer) the firmware drops frames and reports the same count in the counter gaps, the trailer and its own stats; catching up, it read 86 frames right after an SD block, each before the next sample.

## What this does and does not show

Shows: pin/SPI sequencing, ADC reset and register setup, frame CRC, shared-bus scheduling, the ring buffer, FAT32 file handling, log format, run/cal sequence, CAN and drop accounting all work together on realistic signals. Does not show: analog noise, real card timing, the ADC's digital filter delay/droop (corrected offline), or anything about the PCB. Those need the bench tests in spec.md.
